# How to use this vault

Use three passes:

1. **Learn:** follow [[00 Start Here/AI Engineering Curriculum]].
2. **Connect:** follow links from each hub and inspect the maps in `10 Maps`.
3. **Apply:** use the worksheets in `09 Playbooks` and build the staged projects in [[09 Playbooks/Learning Projects]].

Native Obsidian features are enough: wiki-links, properties, callouts, Mermaid, Canvas, search, backlinks, and the graph. No community plugin is required.

## Note conventions

- Hubs explain a domain and point to atomic notes.
- Atomic notes define one concept, its boundary, a mental model, design choices, failure modes, and related links.
- Concept, pattern, and protocol notes end with a **Sources and further reading** section. Each link was checked against the live page on the stated date; the [[11 Glossary and Sources/Sources|source registry]] aggregates the shared set.
- Tool notes are dated snapshots. Re-check their official documentation before making adoption decisions.
- Forecasts are labelled as inference; claims about current behavior have sources in [[11 Glossary and Sources/Sources]].
- Security labs use harmless toy objectives and defensive assertions; they are not recipes for bypassing live services.
- Every note carries a **navigation bar at its end** — `← Previous · Home · Next →` — backed by matching `prev:`/`next:` frontmatter. The bar walks the whole sub-vault in reading order (63 notes, section by section, nothing skipped) and is generated by `~/workspace/aieng-audit/add_nav.py` (see its `CHAIN` list). New notes must be added to that list and the script re-run; it re-verifies the full chain before patching and is idempotent (strips old bars/fields and rebuilds).

## Maintaining notes

- **Update cadence:** Tool and framework notes should be re-verified quarterly or when a major version ships. Concept notes are evergreen — update when the field's understanding materially changes.
- **Adding sources:** When a note's "Sources and further reading" section grows, add the new entry to [[11 Glossary and Sources/Sources]] in the matching bucket. One bullet per source with the claim it grounds.
- **Staleness flags:** Tool notes carry `last_verified` in frontmatter. If a note is older than 6 months, flag it for re-verification before relying on its claims.
- **Validation:** Run the vault validator before committing material changes to catch broken links, missing frontmatter, or duplicate entries.
